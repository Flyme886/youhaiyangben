# local-capture —— 本地版有害样本抓取工具链

把舆情监测导出的 Excel 做成「有害样本」Word 证据册：每条样本 = 编号标题 + 原始链接 + 页面截图。

跑在**本机**：直接用 Ego Lite 真实浏览器 + 持久登录态截图。和仓库里 `skills/harmful_sample/` 那套云服务器链路（Playwright/DrissionPage 无头）是两条独立路线——那套跑在服务器上无人值守，这套跑在有人盯着的本机，风控表现好得多，适合一次一两天内要交几百条的场景。

## 依赖

| 项 | 说明 |
|---|---|
| Ego Lite | 装在 `/Applications/ego lite.app`，CLI 在 `~/.local/bin/ego-browser`；需要先在里面登录目标平台一次 |
| Python | `openpyxl`、`python-docx`；默认取 `~/.workbuddy/binaries/python/envs/default/bin/python`，可用 `PY=` 覆盖 |
| 屏幕 | 至少 1440 宽。窗口被最小化会直接拒截（Ego Lite 的已知行为），被遮挡不影响 |

## 用法

```bash
# 第 1 天：前 400 条，产出「11月10日-抖音-第一批.docx」起
zsh run.sh 监测.xlsx ./day1 --day 1 --rows 400 --date 11月10日

# 第 2 天：第 401-800 条，编号接着昨天最后一条（假设昨天交到第 196 条 / 第四批）
zsh run.sh 监测.xlsx ./day2 --day 2 --rows 400 --start-num 197 --batch-index 5 --date 11月11日
```

| 参数 | 默认 | 说明 |
|---|---|---|
| `--day` | 0（关闭） | 第几天，自动换算成 `--offset/--limit`；**每天扫 400 行** |
| `--rows` | 400 | 每天扫多少行，配合 `--day` |
| `--offset` | 0 | 从去重后清单的第几条开始（0 起算），与 `--day` 二选一 |
| `--limit` | 400 | 本批取多少条 |
| `--start-num` | 1 | 首条编号。**按实际入册条数接，不按行号**——昨天交到 196 就填 197 |
| `--batch-index` | 1 | 批次序号起点，接昨天末批 +1 |
| `--sheets` | `搜索结果,待复核` | 按顺序串成一条清单；表里没有的 sheet 名自动忽略，都没有就用第一张 |
| `--date` | 当天 | 文件名里的日期 |
| `--space` | `有害样本` | Ego Lite 里的任务空间名 |
| `--batch` | 50 | 每份 Word 条数上限 |

输出目录结构：

```
day1/
├── 11月10日-抖音-第一批.docx   ← 交付物
├── screenshots/                ← 0001.png / 0001_hit.png …
└── _work/
    ├── manifest.json           ← 本轮清单（含攻击词、去重键）
    ├── cfg.json                ← 抓取配置
    └── _ego/results_*.jsonl    ← 每条的状态记录（断点续跑靠它）
```

## 单条样本的成稿格式

```
1.标题（微软雅黑 12pt 加粗 #1F4E79，超 32 字截断加「…」）
https://…（9.5pt #0B60B0，照抄原表，不改写）
[主图]        首屏整屏：内容主体 + 作者 + 侧栏
[命中图]      评论命中处放大 + 红框（仅命中时才有）
```

页面 Letter 21.59×27.94cm，左右边距 3.175cm，上下 2.54cm；横图固定 16cm 宽，竖图按 20.5cm 限高。
编号跨文件连续（1..N），每份 ≤50 条，编号在**入册条目**里连续。

## 三条硬规则

1. **只收 `status=ok` 的条目。** 页面明说「不存在 / 已删除 / 内容已失效」的整条不写——标题、链接、截图全不留，编号自动前移。这类只在对话里按平台点名，不进 Word。
2. **没拿到截图的不留空位。** 不写「截图待补」，不编占位符。
3. **区分「删了」和「没抓到」。** 前者静默剔除；后者（验证码、登录墙、超时、出错页、空白）先重抓，两轮仍不行才点名——那是限流造成的缺口，用户要据此决定是否补抓。

## 实现要点（踩过的坑）

**抖音必须点开评论 tab。** 详情页右侧默认是「相关推荐」，评论藏在「评论(N)」页签里；视频页右侧干脆是推荐列表，要点评论图标或数字按钮。校验方式是 `[data-e2e="comment-item"]` 有可见高度的条目 > 0。没点开就截图，截出来的是推荐列表，跟样本无关。

**清晰度靠页面 zoom。** Ego Lite 只开放 `Target.` / `Browser.` 类 CDP 命令，改不了 `deviceScaleFactor`。评论区只有约 300px 宽，直接裁出来放到 Word 里字是糊的。做法是把 `document.documentElement.style.zoom` 设成 1.9 再按视口 `clip` 截图，让浏览器按更大字号重排，像素密度上去了，字就实。

**红框用元素自身的描边。** `box-shadow: 0 0 0 4px #F00 inset` + `outline` 双写，随 zoom 一起缩放。不要用绝对定位的覆盖层——zoom 之后 `position:fixed` 的坐标基准会乱，框会跑偏。

**zoom 之后顶栏会压进视口**，截图前把 `header` 一类元素 `visibility:hidden` 掉。

**没命中就不要第二张图。** 不截「评论区首屏」凑数——那条评论跟样本标题没关系，放进文档只会误导审核人。

**`/share/video/{id}` 会跳验证码中间页**，导航一律改走 `douyin.com/video/{id}`。

**控制权会被抢。** Ego Lite 在同一任务空间里，用户只要手动操作过浏览器，脚本就会被硬停（`listTabs: Control of this task space is with the user`）。`run.sh` 已经包了自动恢复：失败就 `takeOverTaskSpace(空间名)` 再续跑，最多 6 轮；断点续跑靠 `results_*.jsonl`，已完成的条目不重抓。

**节奏。** 单线程，每 12 条重建标签页，撞验证码冷却 60–90 秒。并发会立刻换来验证码成簇。实测每条 10–12 秒（含滚动找评论），400 条约 1.2–1.3 小时。

## 状态判定

| 状态 | 判据 | 归入 |
|---|---|---|
| `ok` | 正常正文 | 入册 |
| `deleted` | 页面明说「不存在 / 已删除 / 内容已失效」 | 剔除，不写 |
| `err_page` | 「出错啦 / 页面加载失败 / 系统繁忙」 | 重载一次再判，仍命中 → 重抓 |
| `captcha` | 安全验证 / 人机验证 / 访问过于频繁 | 重抓 |
| `login_wall` | 只给登录框，正文看不到 | 重抓 |
| `blocked_or_blank` | 正文不足 20 字，且不属上几类 | 重抓 |

判定要准，收录要狠：`deleted` 别把验证码页、空白页、登录墙误判成「删了」；但判准之后就一律剔除。删除判定只在抓取阶段做一次——出稿阶段不要拿「不存在」「已删除」这类字样做二次兜底，正常帖子的正文里完全可能出现这些词，会误杀。

## 已知限制

- 红框命中依赖目标评论能滚动加载到。评论区几千条时，目标评论可能在很深的位置，实测命中率约 50%–70%，其余只交主图，红框需人工补。
- 图片 OCR 类样本（有害信息在配图里）无法 DOM 命中，只能靠主图。
- 小红书需要 `xsec_token`，监测表导出的链接不带 token，直开 404，需回站内搜索补，目前未自动化。
- 今日头条、腾讯新闻在多次密集访问后会转白页，当日补不回来，需隔天再抓。
- 每份 docx 约 20–27MB（内嵌原图），不适合进 Git；交付物留在本地或网盘。
